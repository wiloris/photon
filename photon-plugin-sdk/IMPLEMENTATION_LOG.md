# Implementation Log — photon-plugin-sdk

Формат тот же, что в `photon-core/adapters/*` и `photon-plugin-runtime`:
фиксируется **почему** решение принято, а не что сделано.

---

## Решено внутри SDK

### Wire-кодек продублирован, а не вынесен в общий пакет

**Потребовалось:** SDK должен говорить на том же протоколе, что и runtime.

**Решение:** собственная реализация кодека (`wire.go`), зеркальная к
`photon-plugin-runtime/ipc/codec.go`, но независимая.

**Почему не общий пакет:** его импортировали бы оба, и кусок кода доверенной
стороны попал бы в линковочный граф недоверенного процесса. Формально общий
пакет содержал бы только сериализацию — но это открывает путь: сегодня туда
выносят кодек, завтра «заодно» константы прав, послезавтра валидацию. ADR-031
запрещает не конкретный импорт, а саму возможность такого пути.

**Цена:** расхождение форматов не поймается компилятором. Компенсируется E2E-тестом
против настоящего `ipc.Session`: успешный handshake доказывает побайтовое
совпадение. Без такого теста дублирование было бы неоправданным.

### Все операции проходят через единственный `call`

**Потребовалось:** гарантировать, что ни один метод API не обзаведётся собственной
логикой поверх протокола.

**Решение:** `storageClient`, `identityClient`, `cryptoClient` не содержат ничего,
кроме формирования аргументов и одного вызова `client.call`. Ни условий, ни циклов,
ни обращений к нескольким операциям.

**Почему это структурная гарантия, а не соглашение:** добавить кэш или retry в
отдельный метод, не тронув `call`, невозможно — метод физически не имеет доступа
к сессии, только к `call`. Нарушение видно в diff'е сразу.

### Отмена контекста отправляет CANCEL

**Потребовалось:** отмена на стороне плагина не должна оставлять операцию
выполняться в runtime.

**Решение:** при `ctx.Done()` клиент отправляет `CANCEL` с тем же `request_id`
перед возвратом ошибки.

**Почему обязательно:** без этого отменённая операция продолжала бы занимать
ресурсы **ядра**, а не плагина — то есть плагин мог бы накапливать брошенные
запросы, не платя за них.

### stdin/stdout как канал по умолчанию

**Потребовалось:** определить, как SDK находит runtime.

**Решение:** `Config.Conn == nil` → stdin/stdout. Именно так runtime запускает
плагин (`host/spawner.go`).

**Почему не сокет:** отдельный канал означал бы второй путь наружу и нарушил бы
свойство P6 sandbox («IPC — единственный путь взаимодействия»). Отсутствие сокета
здесь — часть модели изоляции, а не упрощение.

## Решено без изменения контракта (нетривиально)

### Классификация ошибок повторяет коды протокола

**Потребовалось:** дать автору плагина понятные ошибки.

**Решение:** sentinel-ошибки SDK один-к-одному соответствуют кодам `ipc.md`,
включая разделение `ErrUnauthorized` / `ErrForbidden`.

**Почему не упрощать:** соблазн свести их к одной «нет доступа» велик — но эти
случаи требуют разных действий. `UNAUTHORIZED` означает проблему сессии (повтор
бессмыслен), `FORBIDDEN` — отсутствие права (плагин может осмысленно попросить
пользователя). Упрощение в SDK стёрло бы разницу, которую runtime специально
вводил.

**Неизвестный код** отображается в `ErrInternal`, а не игнорируется: он означает
рассинхрон версий, и трактовать его как успех нельзя.

## Найдено E2E-тестом

### Маппинг «операция → право» отсутствовал в реализации

Описан в `sdk-boundary.md` разделом 4 с самого начала Phase 10, но `ipc.Session`
передавал `m.Op` прямо в `Authorizer` как имя права. Unit-тесты не видели этого,
потому что сами использовали имена прав как имена операций.

Проявилось, когда SDK начал слать настоящие операции каталога. Подробности и
решение — ADR-032.

**Урок:** спецификация, описывающая соответствие двух подсистем, требует теста,
который проходит через обе. Тесты, обращающиеся только к одной, могут годами
подтверждать несуществующую согласованность.

## Кандидаты на архитектурное обсуждение

### Проверка синхронности кодеков в CI

Сейчас расхождение форматов SDK и runtime ловится только E2E-тестом. Это работает,
но обнаружение происходит на этапе интеграции, а не при изменении одного из
кодеков.

Возможный вариант — property-тест, гоняющий случайные сообщения через оба кодека и
сверяющий байты. Не сделано: E2E покрывает практический случай, а property-тест
потребовал бы либо общего пакета (запрещён ADR-031), либо копии структур в третьем
месте. Стоит вернуться, если кодеки начнут расходиться на практике.

### Тайм-ауты на стороне SDK

Сейчас дедлайн полностью на стороне runtime; SDK лишь передаёт `context`. Это
правильно (плагин не должен продлевать дедлайн), но означает, что при зависшем
канале вызов ждёт `ctx`, а не быстрый локальный тайм-аут. Практической проблемы
пока нет — стоит вернуться, если появятся жалобы на отзывчивость.
