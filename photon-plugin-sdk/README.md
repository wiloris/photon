# photon-plugin-sdk

Клиентская библиотека для авторов плагинов Photon.

**Статус: skeleton.** Реализации нет.

## Почему отдельный модуль, а не подпакет runtime

Разные trust boundaries (ADR-030):

```
Plugin SDK      ← исполняется ВНУТРИ недоверенного процесса плагина
    │
  Plugin        ← сторонний код
    │ IPC
Plugin Runtime  ← часть платформы, принимает решения о правах
    │
Photon Core
```

Код SDK живёт в недоверенном процессе. Импорт кода Runtime означал бы, что логика
принятия решений о правах компилируется внутрь того, кого она должна ограничивать.

**Зависимости:**

| Может | Не может |
|---|---|
| Стандартная библиотека | `photon-plugin-runtime` |
| (позже) кодогенерация IPC-протокола | `photon-core` напрямую |

Единственный канал связи с Runtime — IPC (`photon-plugin-runtime/docs/ipc.md`).

Плагин не обращается к ядру: он обращается к Runtime, а Runtime — к ядру, проверив
права на каждый запрос.

## Главный принцип (ADR-031)

> **SDK является клиентом уже существующего IPC-протокола и не знает внутренностей
> runtime.**

Разработчик плагина видит:

```
Plugin SDK → IPC protocol → Plugin Host → Supervisor → Sandbox
```

и никогда:

```
Plugin SDK → fork/exec → namespaces / seccomp / cgroups
Plugin SDK → изменение собственных прав
Plugin SDK → управление собственным жизненным циклом
```

Причина не формальная: SDK — единственный компонент, исполняющийся **внутри
недоверенного процесса плагина**. Любая возможность, которую он открывает,
автоматически доступна недоверенному коду. Граница, построенная в Phase 9, обходится
проще всего именно «изнутри» — через библиотеку, которую плагин и так линкует.

**Никаких «режимов разработки», ослабляющих проверки runtime.** Удобство отладки
достигается инструментами вокруг (тестовый хост, Developer Tools), а не флагом,
отключающим enforcement: инструмент можно не поставлять в прод, API в SDK — нельзя.

Вопрос, вокруг которого проектируется Phase 10:

> Как сделать разработку плагина максимально простой, **не позволяя SDK обходить
> security model runtime**?

## Почему пуст сейчас

SDK — клиент уже определённого протокола. Реализация появится после `manifest/` и
`ipc/` в Runtime: писать клиента раньше сервера означало бы проектировать протокол
со стороны недоверенной части.
